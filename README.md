# 质量分析平台（Quality Analytics Platform）

类 Minitab 的工厂质量部门统计分析工具 — 依据 `../design_handoff_quality_platform/` 交接文档,
从设计原型 `质量分析平台.dc.html` 重新实现为 **React 18 + TypeScript + Vite** 应用。

## 运行

```bash
npm install
npm run dev            # Web 端 http://localhost:5188
npm test               # vitest 统计引擎与状态回归测试
npm run build          # Web 生产构建
npm run tauri dev      # 桌面端开发（需 Rust 工具链）
npm run tauri build    # 桌面端打包（macOS 产 .app/.dmg，Windows 产 .msi/.exe）
```

## Windows 桌面端打包

桌面壳为 **Tauri 2**（`src-tauri/`），Web 与桌面共用同一份 UI 与统计引擎。
Windows 安装包需在 Windows 上构建（或走 CI 交叉产出）：

- **CI（推荐）**：仓库已带 `.github/workflows/build-windows.yml`，推 `v*` tag 或手动
  触发 workflow_dispatch，在 windows-latest 上产出 `.msi`（WiX，中文）与 `.exe`
  （NSIS，简中、perMachine），从 Actions Artifacts 下载。
- **Windows 本机**：装 Rust（MSVC 工具链）+ Node 后 `npm ci && npx tauri build`。
- macOS 本机 `npm run tauri build --bundles app,dmg` 可出 mac 版用于开发验证。

平台差异全部收敛在 `src/platform/adapter.ts`（PlatformAdapter，交接文档 §4.2）：

| 能力 | Web | 桌面 (Tauri) |
|---|---|---|
| 导出报表 | Blob 下载 | 原生保存对话框 + Rust `save_text_file` 落盘 |
| 导入数据 | `<input type=file>` | 原生打开对话框 + Rust `read_text_file` |
| 导出载荷 | Excel .xlsx；图文 HTML（打印为 PDF）；Word .docx；PowerPoint .pptx | 同左 |

## 数据导入（真实闭环）

「导入 CSV/Excel」或剪贴板粘贴即可替换活动数据集：自动识别分隔符/表头/数值列，并保留文本分组列。
SPC 可选择行式子组、列式子组、单值列，或「测量值+子组 ID」长表；自动模式仅在角色唯一时推断，
单值自动使用 I-MR。SPC/能力/仪表盘/工作表/导出报告按同一数据角色实时重算。

## 图表主题

三套主题（经典/现代/高对比）+ 网格开关：菜单「工具」内切换,或点击状态栏
「图表风格」标签循环切换。字体已本地打包（@fontsource),桌面端离线可用。

## 功能全景（v1.34）

- **数据**：CSV/剪贴板/**真 .xlsx 工作簿**导入（变量矩阵 n=2..10 / P 图不良数 /
  C 图缺陷数），文本列保留为分组列；**手工录入**（双击单元格编辑、添加子组、悬停
  行号删行,编辑演示集自动转「副本」）；localStorage 持久化 + 最近数据集 +
  **规格限随数据集记忆**；MES 模拟采集流（实时追加子组,SPC 滚动更新）。
- **SPC**：X̄-R / X̄-S / I-MR / **EWMA**（时变限）/ **CUSUM**（双侧累积和）/ P / C,
  Nelson 准则 1–8（并按属性图/变异图适用性限制），展示规则定义、来源、点选明细和分阶段控制限。
- **能力**：Cp/Cpk/Pp/Ppk/CPU/CPL/**Cpm**/Z.bench/σ 水平/PPM;**Anderson-Darling
  正态性检验 + 正态概率图**;非正态时 **Box-Cox** λ 寻优与变换后能力。
- **假设检验**：单因子 ANOVA + **单样本/双样本 t 检验**（Welch,含 95% CI）+
  **相关与回归**（散点图 + 最小二乘 + r/R²/斜率显著性）;引擎实算（F/t 分布 CDF
  经不完全贝塔）;导入数据按所选响应/因子角色实算，形态不满足时明确拦截，不再静默回落无关演示研究。
- **帕累托 / 鱼骨图**：帕累托图 + **6M 因果图**（三上三下鱼骨,问题与原因可编辑,
  localStorage 持久化并随历史记录精确恢复）；内置鱼骨始终标为示例，不冒充用户根因结论。
- **AQL**：表 1 + 正式表 **2-A/2-B/2-C** 方案实时重算、OC 曲线、实际不合格数批判定、责任追溯及正式转移得分/暂停规则。
- **导出（四格式共用当前分析）**：Excel **.xlsx**、图文 HTML（打印为 PDF）、Word **.docx**、PowerPoint **.pptx**
  共用当前 AQL / ANOVA / 单双样本 t / 回归 / DOE / SPC / 能力 / Gage R&R / 帕累托 / 鱼骨图的
  结论、参数、原始分析口径表格和图形，不混入无关演示或通用占位结论；
  「图形 → 下载本页图表 PNG」批量导出当前页图表;Ctrl/Cmd+S/O/P/N 快捷键。
- **工程**：TypeScript + ESLint + Vitest 全量回归；`ci.yml` 每次 push 质量门；
  `release.yml` 推 v* tag 自动发 GitHub Release(含更新器签名 latest.json);
  桌面端「帮助 → 检查更新」经 tauri-plugin-updater 对接 Releases。

## v1.43.0 发布说明（候选，未打标签）

### 兼容性：项目文件格式升到 v5（升级前必读）

- **本版导出的 `.qproj` 使用 formatVersion 5，降级不兼容。** v1.42.x 及更早的版本打不开 v1.43 导出的项目文件，会在格式层直接拒绝，不导入任何内容，并提示「项目文件版本 5 高于当前应用支持的 4,请升级应用」（v1.41.x 显示「支持的 3」，v1.34–v1.40 显示「支持的 2」，v1.33 及更早显示「支持的 1」）。v1.43 不提供导出旧格式的选项。新旧版本混用的工厂：先把所有交换项目文件的机器升级到 v1.43.0，再互传 `.qproj`。
- **各格式版本语义**：v2（v1.34）把 SQLite vault、活动引用、独立 AQL 账本定为不可忽略的项目内容；v3（v1.41）引入分析快照 snapshotVersion=6；v4（v1.42）引入 snapshotVersion=7（MSA 真实追溯字段）；v5（v1.43）新增偏好键 `capabilityWarningAcknowledgement`（1000σ 强警告确认），偏好白名单 `PREFS_STATE_KEYS` 与格式版本绑定，并由写出侧保证两条跨键不变量：活动表与同名最近条目一致，分析数据库没有无卡片引用的孤儿条目。
- **旧文件（v1–v4）先走迁移再导入。** 最近列表中与活动表同名、但内嵌副本与活动表不一致的条目（通常是旧版撤销或写盘失败留下的残留）一律改为跟随活动表（以活动表为准，不比较新旧）；没有分析卡片引用的残留分析数据直接丢弃，不影响任何已保存分析。每项迁移都会在导入提示里逐条说明，迁移后的结果仍要通过全部严格校验。迁移只处理这两类残留，其他跨键矛盾（如 localStorage 与 vault 中的活动表版本不一致）仍按损坏拒绝。v1.29/v1.30 时期没有 snapshotVersion 的 ANOVA/DOE/摘要卡片现在可以随项目导入和导出，回看时如实提示「数据快照缺失」。
- **v5 文件严格校验**：v5 文件中如果出现跨键不一致或孤儿分析数据，一律按损坏拒绝（疑似篡改或回退），因为 v5 写出侧保证不会产生这两类数据。导出时本机残留的孤儿分析数据会先被丢弃，不会再因此阻断整份备份。
- **维护约定**：新增偏好键必须同步提升 `FORMAT_VERSION`。当前守卫测试只能发现偏好白名单被改动、但测试登记表没有同步更新的情况，无法阻止在同一改动里把新键补进 v5 登记表而不提版本号（计划在 v1.43 打标签后冻结 v5 列表并加强守卫）；新增存储键或快照语义同样必须提升版本号，目前都靠代码评审把关。

### 2026-09 全面审查整改要点

- **发布清单按角色核对**：发布 SHA 清单改为以发布角色为键（manifest v2），共 Windows msi、nsis 及各自签名，macOS dmg、更新包及更新包签名，便携版，`latest.json` 9 个角色。本地构建名与 GitHub 改名后的资产名分开匹配，不再错配；缺角色、多资产、角色间字节互换或下载文件与元数据不符都会使转正失败。本地 bundle 目录残留多个 `.app.tar.gz` 时，create 会报 `expected exactly one macos-updater in <目录>; found [...]` 并停止（fail-closed），清理残留后重跑即可。
- **跨版本 `.qproj` 迁移**：见上文兼容性说明。桌面端导入带本机库快照（vault）的项目时，最近列表里带全量数据的条目一并写入本机数据集库（与 vault 同名的以 vault 为准；超出库容量的只保留在最近列表）。不带 vault 的项目（Web 导出或旧版）导入时不写库，其最近条目之后被挤出或点 × 移出最近列表时按只插入方式补存进本机库，因此同样可以找回。在「数据集库」里删除某数据集时，同名最近条目一并移出，不会再被补存回库。
- **分析库上限**：分析数据库在任何时刻都不超过 40 条（`MAX_ANALYSIS_DATA_ENTRIES`），旧条目保留与新条目写入在同一次写入内完成。分析数据库校验失败或被隔离时，不再被当成空库删除。
- **回看、派生、粘贴不再静默覆盖**：回看快照时，如果同名的非活动数据集内容不同，会先另存副本再回放。回看 P 图、C 图、帕累托或鱼骨图记录前，如果当前槽位是用户数据（不是示例），且还没有内容相同的分析记录，会先自动存为分析记录；记录已满（40 条）时取消回看，当前数据保持不变。文件导入、工作表粘贴、导入弹窗剪贴板页签、DOE 生成、随机数据，以及子集/标准化/转置/堆叠这些新建类入口，遇到同名数据集时：内容相同沿用原名；已编辑、内容不同或内容无法核对时另存为「名 (2)」，旧数据集及其规格限不动。唯一例外是 Web 端的确定性派生（子集/标准化/转置/堆叠）：同名旧结果是本会话由同一源表、同一派生得到且之后未经编辑，而源表内容也没变时按原名替换（它可由同一操作重新得到），沿用该名下记住的规格限，并在提示中写明「已替换未编辑的同名数据集」。文件、剪贴板、DOE、随机数据无法重算，一律改名；桌面端一律改名。最近列表最多 5 条：桌面端被挤出的条目以只插入方式归档到本机库。Web 端（没有本机库）最近列表已满时，上述任何新建类写入只要会把带数据的最近条目挤出（不论是否改名），或改名写入会替换已被 × 移出最近列表的当前表，都会先拦截并点名将被移除的数据集；60 秒内重复同一操作（按同一目标名、同一批待移除数据集核对；DOE 各类设计统一按「生成设计」计，设计名里的时间戳和随机种子不影响）即视为确认并移除。新建工作表、另存为副本、回看快照、MES 采集等按名写入的操作不拦截，挤出时提示「已移出最近列表，浏览器端无法恢复」（新建工作表、另存为副本及回看前的自动另存会把这句并入各自的完成提示）。提示按原数据集的实际位置（最近列表、本机库或已移出）生成。
- **最近列表未保存闸门**：拦截前会先用包含活动表最新数据的列表重试落盘，腾出空间后下一次切换自动放行。闸门提示点名当前表，并指向实际存在的入口「文件 → 保存项目文件…」（Ctrl+S）。清空帕累托和恢复演示改走与写入对称的删除簿记，已清空的内容不会再随 `.qproj` 备份复活。
- **清库与导出互斥**：项目导出进行中不允许「清除数据」；正在清库时拒绝导出。两种情况都会给出明确提示。
- **AQL 账本隔离态**：AQL 责任账本损坏或被隔离时，AQL 页显示常驻提示，说明原因和恢复路径。登记、加严/放宽等操作被禁用，项目导出被阻止，AQL 专项报表也拒绝生成，以免产出看似正常的空账本。
- **测试可信度**：修复了测试间模块状态泄漏导致的乱序失败；标准差/均值 CI 黄金锚点改用高精度值，按 6 位小数比对；去掉恒真用例，补上跨窗口分析记录水合的真实守卫。

## 盲审整改（并入 v1.43.0 候选）

在第三方（Codex/Grok）审查之后又做了一轮**盲审**（发现代理禁读任何既有审查报告，独立开轴），成立 15 条（7 P2 / 8 P3，0 误报），全部已修并逐条变异验证：

- **原型键族（P2×2）**：`map[model.name]` 这类按用户输入取值的查表会命中 `Object.prototype`。数据集名为 `__proto__`/`constructor`/`toString` 时，规格记忆查表返回原型成员被判为「有记忆规格」，展开出一个没有 lsl/tgt/usl 的对象，**静默沿用上一个数据集的规格**（能力分析直接算错）。已在唯一入口 `toLookupMap` 收口为 null 原型表，五个读取点全部受益；写入口 `importMatrix` 同时拒绝保留名（此前只在导出侧拦，用户能先建集、之后每次导出项目都失败且无自救路径）。公式引擎的 `t.s in ELEM/CONSTS` 同族问题一并修正（表改 null 原型 + 判定改 `hasOwnProperty.call`，两层各自可被单独变异检出）。
- **备用 Windows 构建的内联 JSON（P2）**：`--config '{"bundle":{...}}'` 在 windows-latest 默认 pwsh 下传给 `npx.cmd` 时双引号被消费，tauri-cli 2.11.4 只收严格 JSON，会以 `key must be a string` 直接失败——备用构建 100% 不可用。改为 `--config` 指向 `.github/tauri.windows-unsigned.conf.json` 配置文件。
- **撤销栈字节预算低估 3–8 倍（P2）**：旧口径只算「数值 8B / 字符 2B」的裸载荷，200k×1 窄表 20 层实测占 244MB 而预算认为 30.5MB，裁剪根本不触发。改为按行/元素/字符串各自计入固定开销（窄表每行是独立 JSArray，最吃亏）。
- **列名无长度闸（P2）**：`renameColumn` 接受 500 万字符列名，绕过单元格上限直接写进 localStorage 与每一层撤销快照。新增 `MAX_COLUMN_NAME_CHARS`，重命名与导入口共用同一常量。

## 图形报告对齐工厂「报告」形制（v1.40.2）

v1.40.1 后用户复核仍指出内容差异。经 LibreOffice 全保真渲染工厂 PPT 逐面板核对,发现并修复三处真实差异:

③**整图形制**为 Minitab「〈测量项〉 的量具 R&R(方差分析)报告」——主标题+表头信息块(量具名称/研究日期/报表人/公差/其他)+无底色居中面板标题(「〈测量项〉 × 部件」等)+y 轴标题(百分比/样本极差/样本均值/平均)。
教训:图形验收必须以**全保真带文字渲染**核对,形状级同构仍会漏掉排序/类别/标题这类内容差异。

## 项目工作台（分析记录对象化）

「保存到项目」把当前分析连同其参数与所属数据集存为一条**记录**:出现在仪表盘
「近期分析记录」与左下「项目管理器」。普通分析点击即**回看**——自动切回当时的数据集、

这让应用从「算完即走的计算器页面」变为以项目为中心、分析可积累可回看的工作台。

**可命名项目**:项目管理器顶部双击即可重命名当前项目,名称随 .qproj 一起持久化,

涉及数据集数与全部分析记录(标题/类型/数据集/关键指标/状态)渲染成一份自包含 HTML
报告,双击即可查看或打印——一眼看清整个项目的分析全貌。

## 公式计算列（对标 Minitab 计算器）

「计算 → 公式计算列…」用一条表达式从已有列算出一列新值,如 `(C1 + C2) / 2`、
`(C1 - mean(C1)) / std(C1)`、`sqrt(C1)`。列可用 `C1 C2 …` 或引号列名 `'直径 (mm)'`
引用;支持 `+ − × ÷ ^`、括号、一元负号,逐元素函数(abs/sqrt/ln/log10/exp/round/sq)
与聚合函数(mean/std/var/min/max/sum/median/range/n,整列折算成常量再广播)。
弹窗内实时预览计算结果并即时报错;引擎为自建递归下降解析器(`src/core/formula.ts`,
纯函数、零依赖、不用 eval,可单测),新列追加后可 Ctrl+Z 撤销。

「编辑 → 查找 / 替换…」(Ctrl+F)按数值批量替换测量单元格(3 位小数显示容差,
可限定列,实时命中数,替换可 Ctrl+Z 撤销)。「数据 → 子集 / 条件筛选…」复用同一引擎,按条件表达式筛出子集为新数据集。除算术外,
表达式还支持比较(`> < >= <= == <> !=`,单 `=` 视为等于)与逻辑(`and / or / not`)运算,
如 `C1 > 25`、`C1 >= 24.9 and C1 <= 25.1`、`not (C2 = 0)`;逻辑真值判定排除 NaN。弹窗
实时显示命中行数,条件为真的行保留到新数据集「… (子集)」,原数据集不变。

## DOE 接真实数据（v1.24.0,响应质量工程师验收反馈·批次B）

针对「DOE 只能看内置 2³ 演示、无法分析自己的实验数据」的反馈,把实验设计模块
从写死的三因子示例升级为**通用两水平全因子引擎**(k=2..4),分「创建设计」与
「分析设计」两条真实数据链路:

- **创建因子设计**:填因子数(2–4)、各因子名与上下限、中心点数、重复数、是否随机化,
  一键生成规范设计表(Yates 标准序 + 中心点取上下限中点 + 确定性 LCG 随机运行序)
  写入工作表,末列「响应(待录入)」留空待试验录入。
- **分析因子设计**:用列选择器勾选因子列与响应列,引擎自动把每个因子识别为 2 水平
  (含中心点=中值),按正交编码算主效应与全部交互(系数 β=Σ(y·x)/Σ(x²)、效应=2β)。
  **有重复或中心点(残差自由度>0)走 t 检验**(给出标准化效应、P 值),
  **饱和设计走 Lenth PSE**(伪标准误 + 显著界限);主效应图/交互作用图(任意因子对)/
  效应帕累托(t 临界或 Lenth 界限)/立方图(3 因子)与**残差四合一诊断**全部按真实数据出图。
- **数据形态不符时给显式原因**:因子多于 4、水平数不为 2(或 3 但中值不在中点)、行数不足
  都会明确提示,并引导去「创建因子设计」生成规范表,不再静默套演示。出厂演示集仍显示 2³ 示例徽标。
- 引擎为纯函数(`src/core/doe.ts`:`detectFactorial` / `analyzeFactorial` /
  `generateFactorialDesign`,零依赖、可单测),`factorial.test.ts` 覆盖与旧 Lenth 一致性、
  含重复的 t 检验路径、含中心点的设计生成。

## 两轮外部审核纠偏(v1.25.0)

在 v1.24.0 后引入 **Codex 与 Cursor(Grok)两个独立模型**做只读代码审核,连同内部对抗审查一并核对。
两轮共确认 11 处真缺陷(0 处被推翻),本版全部落实——其中 3 处是 DOE 引擎里内部审查漏掉的:

- **DOE 未录入拦截**:生成设计后响应列为占位 0、未录入就点分析,过去会给出 P=1.000 等"正式结论"。
  现检测响应列无变异即拦截,提示先按运行序录入,不再把"尚未采集"当成"实测为 0"。
- **零残差非零效应**:完美拟合(MSE=0)时非零效应过去被判"不显著"(方向反了),现修正为无穷显著(p→0)。
- **分数设计别名**:`C=A×B` 等别名结构过去保留交互、丢弃主效应;项枚举改低阶优先,现保住主效应。
- **ANOVA 数值因子模式**:新增"选一数值列作因子(按取值分组)+ 一列作响应"——刘润泽那套
  "压入力 按 过盈量/轴硬度 水平"的单因子 ANOVA 现可正确做出;异量纲宽表给强告警,摘要标"存疑"不再固化无意义的显著 P。
- **SPC 判异一致性**:准则 4 的结果列表改记实际越界点(红点/列表/点击详情三者一致);极差(R/S/MR)图也判异并显示失控点。
- **柏拉图解析**:唯一数值列即使是 1,2,3 也不再当序号删;识别"频率"表头。
- **AQL 方案表**:按当前检验水平重画(水平 I/III 的批量范围与字码不再自相矛盾)、覆盖到批量 15 万、批量输入下限校验。
- **帕累托 80/20**:改判"累计达 80% 所需类别占比",不再"前两类≥60% 即称符合 80/20"。
- **保存快照完整**:ANOVA 模式/列、DOE 因子/响应列纳入分析记录快照,回看与保存时一致。
- **DOE 标准化残差**:四合一改用标准化残差 r/(s·√(1−杠杆)),对标 Minitab。
